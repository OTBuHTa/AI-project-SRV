# ADR-011 — AI action proposals require deterministic policy and post-execution verification

## Status
Accepted for v0.1.5-alpha.

## Decision
AI-project SRV may let the assistant *propose* an infrastructure change, but the LLM never selects an arbitrary executable command. A proposal must map to a server-side allowlisted capability, pass the Policy Engine, remain `pending_approval`, and be explicitly approved by a permitted user.

The first supported proposal is `docker.container.restart` (risk level 2). After the agent reports command success, the ActionPlan transitions to `verifying`, not directly to `succeeded`. A later fresh heartbeat must independently observe the target container in `running` state before the plan is marked successful.

## Rationale
Exit code 0 proves only that a command returned successfully; it does not prove that the intended infrastructure state is healthy. Separating execution from verification makes audit records stronger and creates the foundation for future rollback and SLO-aware automation.

## Safety constraints
- No arbitrary shell generated by the LLM.
- Capability and parameters are validated server-side.
- Container must exist in the most recent inventory.
- Approval remains mandatory.
- Verification uses fresh agent observation rather than command stdout.
